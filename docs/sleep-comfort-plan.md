# 「今晚怎么睡」——把天气翻译成今晚的三个动作

状态：已实现（2026-10-26）

## 1. 问题

首页天气卡只回答了「今天几度」，没有回答「今晚这觉怎么睡」。同一张卡上的城市、温度、湿度与睡眠记录之间没有任何连接：用户看完天气，仍要自己判断盖什么被子、开不开空调。而这类判断恰好是温度、湿度、风力、降水四个变量一起决定的，凭感觉容易出错——热天盖厚被、干冷天开整夜暖气，都是常见的反向操作。

## 2. 目标与非目标

**目标**

1. 用一条能直接照做的结论替代「今天 26°」这类原始读数：盖什么被子、开不开空调、空气怎么处理。
2. 与既有睡眠流程衔接：卡片紧邻「开始入睡」，详情里可以直接开始今晚的会话。
3. 判据可解释：每个结论都写清依据（夜里最低温、湿度、风、降水），用户能自己复核。

**非目标**

- **不预测睡眠质量。** 天气不是睡得好不好的充分条件，把它写成「今晚会睡得更沉」是伪造因果。
- **不测室内。** 应用拿不到卧室温湿度，所有数值都是城市级预报的推导结果，必须如实说明。
- **不做个性化学习。** 不根据历史记录反推「你适合 24°」，样本量根本不够。
- **不新增权限、不新增网络请求。** 复用首页已有的那一次天气请求。

## 3. 产品方案

### 3.1 位置与形态

首页信息流（手机端）：头部时间+天气 → 昨夜 hero → 阶段条 → **今晚怎么睡** → 昨夜对比结论 → 开始入睡 → 工具卡 → 历史。

选这个位置的理由：它必须排在「开始入睡」之前才构成行动建议，又不能排到昨夜回顾之前打断「先看昨天」的阅读顺序。宽屏沿用同一顺序，落在左栏。

两种形态：

| 形态 | 内容 |
|---|---|
| 折叠（首页卡片） | 标题「今晚怎么睡」+ 依据行（现在 24°，夜里最低 18°）+ 一句结论 + 三行要点（被子 / 空调 / 空气） |
| 展开（底部弹层） | 今夜天气概况、三条建议各自带「依据 + 做法」、目标室温与湿度、如实说明数据来源，底部主按钮「开始入睡」 |

卡片整体可点，但**只点开详情，不会触发权限框或开始睡眠**——首页那颗定位胶囊已经证明，整卡可点必须对应「看到更多」，不能对应一个副作用动作。

### 3.2 判据：只看今夜，不看此刻

睡眠发生在夜里，所以被子与空调按**今夜最低温**（`temperatureMin`，若当前温度更低则取当前温度）分档，而不是按此刻温度。此刻温度只用于写依据行与「睡前先把积热排掉」这类动作。

分档阈值与对应的动作：

**被子（按今夜最低温）**

| 今夜最低 | 结论 | 说明 |
|---|---|---|
| ≥ 27° | 只搭一角 | 不盖或只搭薄巾，护住腹部即可 |
| 24–27° | 夏凉被，单层 | 热了可以只盖到腰 |
| 21–24° | 薄被，2–3 斤 | 最常见的夏末初秋档 |
| 17–21° | 中等厚度，4–5 斤 | — |
| 12–17° | 厚被，6 斤以上 | 可再加一条薄毯压脚 |
| < 12° | 厚被加毛毯 | 注意肩颈和脚别漏风 |

**空调（按今夜最低温 + 湿度）**

| 条件 | 结论 | 说明 |
|---|---|---|
| 今夜最低 ≥ 27° | 制冷 26–27° | 睡前 1 小时开，睡着后切睡眠模式或定时 3 小时；风向朝上，别对着床 |
| 24–27° 且湿度 ≥ 75% | 除湿 26° | 这种天气除湿比降温有用，降到 55% 左右可以关 |
| 24–27° | 风扇低档 | 不用开空调；摇头、别直吹 |
| 17–24° | 不用开 | 睡前开窗换气 20 分钟 |
| 12–17° | 制热 18–20°（怕冷再开） | 睡前预热，睡着后可以关 |
| < 12° | 制热 18–20° | 别超过 22°：室内外温差太大，起床更难受 |

**空气（按湿度，缺数据时不出现这条）**

| 湿度 | 结论 |
|---|---|
| ≥ 75% | 除湿到 55%，被子选棉麻透气材质 |
| 65–75% | 睡前除湿 1 小时，或开窗对流 |
| 40–65% | 刚好，不用处理 |
| 30–40% | 加湿到 45–55% |
| < 30% | 加湿器加一盆水，注意鼻咽发干 |

**通风（并入空调那条的说明，避免自相矛盾）**

有雨、雪、雾或降水量 > 0 → 整夜关窗；风速 ≥ 20 km/h → 只留一条缝；否则在「不用开空调」的档位里给「睡前开窗 20 分钟」。

### 3.3 文案

一句结论由「空调动作 + 被子动作」拼成，避免给每种组合手写一句：

> 开空调 26°，被子只搭一角
> 不用开空调，盖中等厚度的被子
> 暖气 18–20°，厚被加毯

不用「应该」「必须」这类命令句，也不承诺效果。判据行永远是数字：「现在 24°，夜里最低 18°，湿度 68%」。

### 3.4 降级与边界

| 情况 | 表现 |
|---|---|
| 天气请求失败 / 无位置 | **整张卡不出现**。没有天气就没有建议，不用占位卡解释为什么没有 |
| 湿度缺失 | 只出「被子」「空调」两条，详情写明「这次天气没有湿度数据，建议只按温度给出」 |
| 极端温度（> 45° / < −30°） | 仍按最高/最低档给结论，不特殊提示——这种天气下「厚被加毯」已经是最合理的话 |
| 深夜打开 | 结论不变（判据是整夜最低温），只是依据行显示当前温度 |

### 3.5 与睡眠的结合点

1. 位置紧邻「开始入睡」。
2. 详情弹层底部直接放「开始入睡」主按钮，点完关闭弹层并进入会话。
3. 不新增设置项、不改数据库、不加权限。

## 5. 验收

- 任一温度档位下，结论与第 3.2 节表格一致（单测覆盖每档边界）。
- 湿度为 `null` 时，卡片只显示两条要点，且不含任何湿度数字。
- 天气不可用时首页不出现空白占位或「暂无建议」。
- 详情弹层在 430×932 的手机尺寸与宽屏下都不溢出，深浅主题均使用 token 颜色。
- `dart analyze` 与 `flutter test` 通过。

## 6. 已知局限

- 判据是城市级预报，不是卧室实测；同一城市不同楼层、朝向能差 2–3°。
- 只覆盖今夜，不支持查看明晚；接口虽有 `date` 参数，但首页只取当天。
- 「空调 26°」是通用建议，不区分地域习惯与房间面积。
