# 底部模糊带设计（2026-09-29）

> 日期：2026-09-29
> 状态：设计已裁定并实现（v2.8，2026-09-29）
> 范围：在屏幕底部新增一条常驻的渐变模糊带（`.ios-bottom-fade` 的对应物）
> 设计基准：[夜深项目规格说明书](2026-09-28-night-sleep-design.md)。本文新增一条偏差（#22），
> 并修订其第 2 章「材质与几何」。

## 来源与现状

用户在一轮实机使用后提出：**底部也加一条轻微的渐变模糊带，让滚到标签条附近的内容糊掉**。
这不是缺陷修复，是新增。**原型源文件（Figma Make 导出的 `index.css` / `index.html`）不在仓库里**，
所以原型底部是否有对应的带无法核实；用户已确认**原型没有**，因此计入偏差表（主规格 #22）。

现状取证：下面这组数字是在 iPhone 16 Pro 模拟器上逐像素扫描截图所得，但那批截图是**改动前
（标签条浮起量仍为 34pt 时）**拍的——它记录的是「没有这条带子」的现状，不是本节落地后的样子。
标签条下方那段**没有任何过渡**——列表滚到该区域时文字完全清晰：胶囊底边在屏幕底上方 34.0pt
处结束，而它下方直到 home indicator（顶边 12.7pt）之间的内容（记录卡的「23:15 → 07:20」一行）
逐字可读，没有模糊也没有变淡。

`top_fade.dart` 已经解决过一次同类问题（内容滚进状态栏时把它淡出），底部这条是它的镜像。
两者共用同一套技术，但**参数不同**：顶部带是为「遮住状态栏」调的，底部带对着的是浮动的玻璃胶囊。

## 已裁定的决策（用户已确认）

| # | 决策 | 取值 | 理由 |
| --- | --- | --- | --- |
| 1 | 出现时机 | **常驻**，不与滚动联动 | 用户选定。实现最简单，也最接近 iOS 工具栏底衬的观感；代价是滚到底时最后一行的下缘会落在带子的过渡区里被轻微模糊 |
| 2 | 高度 | `tabBarReserve(context) + 20`（iPhone 16 Pro 上 **121pt**） | 由标签条的预留量推导，不写死。胶囊顶边离屏幕底 85pt，多出的 36pt 是「内容在碰到胶囊之前先化开」的过渡段 |
| 3 | 模糊与填充强度 | `blur(14)`；填充 `bgBase` **0 → 78%** | 模糊半径与顶部带一致（两条带要像一套）；填充比顶部带的 92% 弱一档，因为用户要的是「轻微」 |
| 4 | 原型归属 | 原型没有，**新增** | 计入主规格第 8 章偏差 #22 |

## 设计

### 组件

新增 `lib/core/widgets/bottom_fade.dart` → `BottomFade`。它是 `TopFade` 的镜像，但**没有 `visible`
参数**（常驻），因此也没有 `AnimatedSlide` / `AnimatedOpacity`。

```dart
const BottomFade({super.key, required this.height});
```

`height` 必填、不给默认值：带子的高度必须由**标签条的实际预留量**推出，写死一个 120 会让两者在
别的机型上脱节（同 v2.7 把浮起量与底部留白收成 `tabBarFloat` 一处的理由）。

### 放置与 z 序

放进 `AppShell` 的 `Stack`，**位置在 `_TabBar` 之前**：

```
Stack
 ├─ 页面内容（各页自己的滚动视图）   ← 被模糊的对象
 ├─ TopFade（已有）
 ├─ BottomFade（新增）              ← 只模糊「已经画出来的」内容
 └─ _TabBar（已有）                 ← 画在带子之上，自己保持清晰
```

顺序不可颠倒：`BackdropFilter` 模糊的是**它之前**画好的东西。带子若排在标签条之后，
它会去模糊玻璃胶囊本身，胶囊就糊了。

### 几何

| 量 | 取值 | 说明 |
| --- | --- | --- |
| 带子高度 | `tabBarReserve(context) + 20` | 在 `AppShell` 调用处推导。`core/` 不能反向依赖 `app/`，所以推导只放调用处，组件本身只收一个 `height` |
| 带子横向 | 屏幕满宽 | 与 `TopFade` 同；底部这条要盖住胶囊左右两侧的内容 |
| 带子底边 | 屏幕物理底边 | 与标签条、home indicator 同一参照系 |

iPhone 16 Pro 上：预留 101 + 20 = **121pt**（预留 = 胶囊 65 + 浮起 20 + 呼吸 16，由
`test/tab_bar_inset_test.dart` 钉住）；macOS / Web 等无安全区处：93 + 20 = **113pt**。

### 渐变方向（整体镜像）

顶部带的遮罩与填充**两重衰减都朝下**。底部带必须整体反向，否则出现「底部最淡、上方最重」的
逆向观感——那是把顶部代码抄下来最容易犯的错。

| | 顶部带 | 底部带 |
| --- | --- | --- |
| 遮罩 `ShaderMask` 颜色（上→下） | 黑 → `0x85000000` → 透明 | **透明 → `0x85000000` → 黑** |
| 遮罩停点 | 0 / .34 / .68 / 1 | 0 / .32 / .66 / 1 |
| 填充 `bgBase` 透明度（上→下） | 0.92 / 0.72 / 0.32 / 0 | **0 / 0.27 / 0.61 / 0.78** |
| 填充停点 | 0 / .38 / .70 / 1 | 0 / .30 / .62 / 1 |
| `BackdropFilter` | `blur(14)` | `blur(14)` |
| accent 叠加（`saturate` 近似） | `alpha 0.04` | `alpha 0.04` |

填充的中间两档由顶部带的曲线按 `0.78 / 0.92` 缩放得到，保持同一条衰减曲线，只是顶端压低。

### 两个必须照搬的写法（都是已记账的坑）

1. **遮罩套在 `BackdropFilter` 外面。** `BackdropFilter` 模糊的是它子树**之外**身后画好的画面，
   套在里面的 `ShaderMask` 只管得到填充，模糊会留一条硬边（`top_fade.dart` 里记着这条）。
2. **`Stack` 的每个子项都要 `Positioned.fill` / `SizedBox.expand`。** `StackFit.loose` 下
   `Stack` 按最大的非 position 子项定尺寸，无子节点的 `DecoratedBox` 会缩成 0×0，整条带凭空消失。

### 边界情况

| 情况 | 行为 | 理由 |
| --- | --- | --- |
| 宽屏（≥768px） | **不渲染** | 那里是侧边栏布局，没有浮动标签条；画一条没人坐的带子只会平白压暗底部。与 `TopFade` 同规则 |
| 底部弹层打开时 | **不收起**（照常显示） | `TopFade` 收起是因为原型如此；这条带是新增的，弹层的蒙层本来就盖住整屏，带子只是跟着一起变暗。此时专门收起反而会在开弹层那一瞬闪一下 |
| 二级页 | 不存在 | 二级页 `push` 在 `AppShell` 之外，天然没有带子——与标签条一致 |
| 内容不足一屏 | 照常显示 | 常驻的代价，用户已确认接受 |
| 手势 | 完全不拦 | 整条带外面套 `IgnorePointer` |

## 已知副作用（实现时确认，不预先「解决」）

带子画在标签条之下，所以**玻璃胶囊的 backdrop 会看到已经被洗过一遍的内容**：胶囊所在那一段
（离底 20–85pt，对应带子从顶部数起的 0.30–0.84 处）经遮罩衰减后的有效填充 alpha 从胶囊顶边的
约 **0.13** 升到胶囊底边的约 **0.71**（填充 0.27→0.71 乘遮罩 0.48→1.0），胶囊下半部因此比现在
更「实」、更少透出内容细节。

iOS 上「底衬 + 悬浮玻璃条」本来就是这个层次关系，预计观感成立；但这是**本次唯一无法靠断言
判断的取舍**，实现后需要用截图人工核对一次。若看起来发闷，可调的旋钮是填充曲线（压低 78% 这一端），
不是把带子挪到胶囊之上。

## 非目标

- **不做滚动联动**（隐藏 / 淡出）。用户选了常驻；若日后要改，改的是 `AppShell` 给不给它 `visible`，
  与组件本身无关。
- **不引入 `saturate` 的真实实现**（`ColorFilter.matrix`）。沿用顶部带现有的 accent 叠加近似，
  保持一致；要改就两条带一起改。
- **不为带子单独立动画时长常量**。常驻，没有动画。
- **不动 `app_toast.dart` 里写死的 `bottom: 100`**（见「待核实」第 3 条）。

## 待核实事项（实现第一步就要验证，不得当成已知）

1. **`ShaderMask` 的镜像方向在真机上确实呈现为「下重上轻」。** 断言只能证明色标顺序，不能证明
   合成结果符合预期；实现后跑一次模拟器截图核对。**已核实（2026-09-29，iPhone 16 Pro 模拟器）**：
   越靠近屏幕底越实——浅色统计页上胶囊下方那段的「平均时长」只剩很淡的残影、深色首页上胶囊下方的
   内容被洗到接近 `bgBase`（黑），而带子上方的内容（「推荐 7–9h」「雨声·海浪·篝火」）保持清晰；
   带子顶边（离屏幕底 121pt）无硬边（离带顶约 20pt 处有效 wash 约 9%，越往下越重）。覆盖面：浅色
   首页（滚动后）/ 统计页 / 详情与助眠音效弹层，**深色仅首页静置态**。
2. **胶囊压在被洗过的 backdrop 上观感可接受**（见「已知副作用」）。**已核实（2026-09-29）**：
   胶囊下半部未发闷——浅色下胶囊仍通透，深色下仍读作正常的玻璃条（`bgNavbar` 76% 填充主导）。
3. **toast 的位置是否要跟着走。** `app_toast.dart:62` 把手机布局的底部偏移写死为 `100`，
   这个值是按旧标签条位置算出来的（v2.7 之前胶囊顶边在 99.5pt，只留 0.5pt 间隙），
   v2.7 之后变成 85pt、间隙 15pt。本轮**不改它**，但要知道它是第二个写死的镜像值。
4. **底部多一层 `BackdropFilter` 的性能开销**（顶部已有一层，胶囊自己也有一层）。
   在模拟器上滚动时观察是否掉帧；若明显，考虑合并层次。
