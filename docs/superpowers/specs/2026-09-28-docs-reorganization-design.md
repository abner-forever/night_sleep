# 文档重组设计

> 日期：2026-09-28
> 状态：已完成（2026-09-28）
> 范围：只动文档，不动 `lib/` 下任何代码

## 问题

项目当前有三份文档，都在根目录，职责互相重叠：

| 文档 | 行数 | 现状 |
| --- | --- | --- |
| `README.md` | 225 | 环境、命令、结构树、实现范围、构建前提、验证记录 |
| `CLAUDE.md` | 153 | 命令、架构、陷阱、测试注意、约定 |
| `PROJECT_SPEC.md` | 288 | 设计基准，头部挂着 v2.0→v2.4 的变更史 |

已经出现重复，且都是「同一事实写多遍」的典型后果（下列位置经 grep 实测确认）：

1. `132 项测试` 这个数字写在 `CLAUDE.md:24` 与 `README.md:187` 两处。改一次测试要记得改两处。
2. 13 个测试文件的逐项清单在 `README.md`「验证记录」与 `PROJECT_SPEC.md` §9 各列一遍，两份口径还不完全一致。
3. `flutter pub get` / `build_runner` 等命令在 `README.md` 与 `CLAUDE.md` 各有一份；`DEMO_DATA` 开关的说明也重了两处。
4. `PROJECT_SPEC.md` 的引用散在四处：`README.md:3`、`CLAUDE.md:10`、`CLAUDE.md:15`、`CLAUDE.md:101`。文件一改名，四处全断。

另有一处**看似重复但并不重复**，明确不做合并：`README.md` 的「项目结构」是文件地图，`CLAUDE.md` 的「架构」是分层规则与约定（如「Widget 不直接碰数据库」）。两者读者与用途不同，保持原样。

此外，`PROJECT_SPEC.md` 头部的变更史随版本增长，会把真正的规格正文越推越远；而 superpowers 的约定是把设计与实现计划放在 `docs/superpowers/{specs,plans}/`，文件名带日期。项目目前没有 `docs/` 目录。

## 目标

采用 superpowers 的目录约定，同时按**读者**重新划定职责边界，让每个事实只有一个归属。具体到可检验的程度：

- 任何一条事实，能在文档树里指出唯一的「拥有者」。
- 修改测试数量、命令、目录结构时，只需要改一处。
- 读者（人或 agent）知道该翻哪份文档。

## 目标结构

```
README.md                                                 人看的：怎么跑、能干什么
CLAUDE.md                                                 agent 看的：动手前的约束与陷阱
CHANGELOG.md                                              版本史
docs/superpowers/specs/2026-09-28-night-sleep-design.md   设计与验收基准
docs/superpowers/plans/                                   实现计划（以后的新功能落这里）
```

`PROJECT_SPEC.md` 的正文迁到 spec 路径，除下面列出的两处外逐字保留。它此前是「活文档」（版本 2.4，原地迭代），迁移后维持这一模型：文件名日期取首次创建日，后续原地更新，不再新开文件。

迁移时对正文只做两处改动：

1. 删去头部 v2.0→v2.4 的变更史段落，另行落成 `CHANGELOG.md`。
2. 第 9 章覆盖矩阵去掉逐项用例计数（理由见「重复消解清单」第 2 条）。

除此之外一个字不改——包括 17 条偏差表的措辞、各章的表格与代码块。

头部那段 v2.0→v2.4 变更史剥离到根目录 `CHANGELOG.md`，按 Keep a Changelog 的惯例倒序排列（最新在上）。spec 自身保留一行版本标识：

```markdown
> 版本：2.4（2026-09-28）
> 变更史见 [CHANGELOG.md](../../../CHANGELOG.md)
```

绝对路径不用，全部用相对路径，以便文档随仓库移动。

## 职责边界

判断标准是**读者**，不是主题：

| 文档 | 唯一职责 | 拥有的内容 |
| --- | --- | --- |
| `README.md` | 怎么跑起来、现在能干什么 | 环境要求、完整命令、项目结构树、当前实现范围、未实现表、构建网络前提、真机安装、截图巡检、平台配置、最近验证记录 |
| `CLAUDE.md` | 动手前必须知道的 | 指针、高频命令、「Flutter 与 CSS 语义不同」五类陷阱、测试注意、其他约定 |
| spec | 做成什么样 | 原 1–7 章、第 8 章偏差表、第 9 章覆盖矩阵、第 10 章外部资料 |

同一个事实若对人是「怎么操作」、对 agent 是「避坑」，两边都可以出现，但一侧写全文、另一侧写一句加链接。

`PROJECT_SPEC.md` 第 8 章的 17 条有意偏差是产品红线（不伪造睡眠阶段 / 不画没有真实音频的波形 / 不显示读不到的余额 / 不猜小米导入字段），CLAUDE.md 保留「动手前先读」的指示，只更新指向的路径。

## 重复消解清单

| # | 现状 | 处理 | 归属 |
| --- | --- | --- | --- |
| 1 | `132 项测试` 写在两处 | 只留在 README 验证记录一处，作为那次运行的实测输出；CLAUDE.md 的命令注释不再出现数字 | `README.md` |
| 2 | 13 个测试文件逐项清单在 README 与 spec §9 各一份 | spec §9 拥有「覆盖了哪些场景」（保留场景描述与测试文件路径，去掉逐项计数）；README 验证记录压缩为「命令 + 结果 + 日期 + 环境」 | spec §9 |
| 3 | 命令在 README 与 CLAUDE.md 各一份 | README 拥有完整版（含镜像、iOS 构建前提）；CLAUDE.md 只留高频命令，镜像与构建前提指向 README | `README.md` |
| 4 | `DEMO_DATA` 说明重两处 | README 拥有完整说明；CLAUDE.md 删去该段，改为一句指向 README | `README.md` |
| 5 | 四处 `PROJECT_SPEC.md 第 N 章` 引用 | 全部改指 `docs/superpowers/specs/2026-09-28-night-sleep-design.md` | 全部 |

第 2 条是唯一会改变信息量的一条：README 的「验证记录」目前逐文件列出 13 项测试及各自用例数，这些内容与 spec §9 的覆盖矩阵重复，且 README 的版本天然会过期。压缩后 README 记录的是**某一次验收在什么环境下跑出了什么结果**，spec §9 记录的是**哪些场景被覆盖**。两者互补，不再重复。

## 非目标

- 不重写正文措辞，不调整章节顺序。
- 不改 `lib/` 下任何代码，不改测试。
- 不动 `screenshots/`（该目录已 gitignore）。
- 不新增 `docs/README.md` 索引文件。
- 不为 `M2`/`M3`/`M4` 写任何新的 spec 或计划——本次只做迁移。

## 风险与对策

**风险：搬迁时正文被无意改写。** 对策：spec 正文整体搬迁，改动只限上节列出的两处加内部交叉引用；搬迁后逐段比对，确认差异仅出现在预期位置。

**风险：引用路径漏改。** 对策：全仓搜索 `PROJECT_SPEC` 字面量，逐一处理，改完再搜一次确认为零。

**风险：README 验证记录压缩后丢失历史信息。** 对策：被压缩掉的逐文件清单在 spec §9 中有等价内容，不构成信息丢失；压缩前后人工核对一遍覆盖范围一致。

## 验收方式

1. 全仓搜索 `PROJECT_SPEC` 无残留引用。
2. 搜索 `132`（排除 `docs/` 与 `.superpowers/`）只在 `README.md` 出现一次。命令为 `grep -rnw --exclude-dir=docs --exclude-dir=.superpowers "132" --include="*.md" .`——`-w` 与两个 `--exclude-dir` 都不可省：少 `-w` 会假命中 `CHANGELOG.md` 里的十六进制色值 `#101322`；排除 `docs/` 是不把本次的记录文档算作重复——本次的设计文档与实现计划为了说明「改前长什么样」会引用这个旧数字，那是记录，不是重复；排除 `.superpowers/` 是不把任务台账算进来。用 `--exclude-dir` 按目录排除而不是用管道按内容过滤，是因为后者依赖具体 grep 实现输出的路径是否带 `./` 前缀，脆。
3. `docs/superpowers/specs/2026-09-28-night-sleep-design.md` 与迁移前的 `PROJECT_SPEC.md` 逐段比对，差异只出现在头部变更史、第 9 章计数，以及修复轮补录的两项场景。**注意：`PROJECT_SPEC.md` 从未入 git 且已删除，字节级比对现已不可复现**——实际依据是行数等式与内容级旁证，详见 `.superpowers/sdd/2026-09-28-docs-reorganization/progress.md`。
4. spec §9 的覆盖场景在压缩 README 验证记录后仍全部可查。
5. `flutter analyze` 与 `flutter test` 结果不变（本次不动代码，用来证明确实没动到代码）。
