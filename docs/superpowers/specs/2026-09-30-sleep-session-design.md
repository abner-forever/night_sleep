# 睡眠会话与回顾设计

> 日期：2026-09-30
> 状态：设计已定，待实现
> 范围：应用显示名改为中文；新增「开始睡眠」入口与动态睡眠会话页；「记录」Tab 改为「回顾」Tab；
> 起床闹钟接真实本地通知
> 设计基准：[夜深项目规格说明书](2026-09-28-night-sleep-design.md)。本文不重复其第 8 章的产品红线，
> 但受其约束——不伪造数据、不让控件声称自己没有的能力、演示数据与真实数据隔离。

## 问题

现在的应用只会在**早晨**用一次：昨晚睡了多久、睡得怎么样，全靠事后回忆手填。用户提出的两点：

1. **应用显示名还是英文**。iOS 桌面显示 `Night Sleep`，macOS 与 Web 显示 `night_sleep`，
   而应用内、文档里都叫「夜深」。
2. **没有「开始睡眠」这个动作**。原型 NAV 里的「记录」Tab 是一张手动录入表单，它假设用户
   记得住昨晚的入睡时刻。实际使用中，睡前那一下才是真正有信息的时刻——那会儿人还醒着。
   夜里该由应用陪着（白噪音、起床闹钟），早晨醒来时起止时间已经是真的了，用户只需要补主观感受。

第 2 点的后半段是这次真正的结构调整：**把「录入」和「补充感受」拆成两件事**。
前者变成睡前按一次按钮，后者变成醒来后的一屏。

## 非目标

- 不实现夜间录音（M3）。会话页的「鼾声/梦话记录」开关**只保存偏好**，副标题如实写明。
- 不实现后台播放与锁屏音频控制（M3）。会话页的白噪音如实标注「退到后台或锁屏后声音会停」。
- 不自动判定打鼾、说梦话或任何睡眠阶段。会话产生的记录**没有任何阶段数据**，
  醒来后的四类事件标记**全部留给用户自己勾**。
- 不申请精确闹钟权限（`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`），不使用需要 Apple 特批的
  `critical` 提醒级别。
- 不申请麦克风权限。
- 不改小米导入、AI 洞察、导出与既有提醒（就寝/起床日常提醒）的行为。

## 新增依赖

**无。** 这次的每一块都落在已有能力上：会话状态进已有的 Drift 库、通知走已有的
`flutter_local_notifications`、白噪音用已有的 `noise_synth` 合成、页面用已有的令牌与组件库。
`pubspec.yaml` 一个字节都不动。

## 一、应用显示名

| 位置 | 现状 | 改为 |
| --- | --- | --- |
| `ios/Runner/Info.plist` · `CFBundleDisplayName` | `Night Sleep` | `夜深` |
| `macos/Runner/Info.plist` | 无此键 | 新增 `CFBundleDisplayName = 夜深`（沿用 `$(PRODUCT_NAME)` 会得到 `night_sleep`） |
| `web/index.html` · `<title>` 与 `apple-mobile-web-app-title` | `night_sleep` | `夜深` |
| `web/manifest.json` · `name` / `short_name` | `night_sleep` | `夜深` |

**`PRODUCT_NAME` 保持 `night_sleep` 不动。** 它决定 macOS 的 `.app` 包名与可执行文件名——
改成中文会让构建产物路径变成中文，并顺着 `EXECUTABLE_NAME` 影响一串构建设置。而 Dock、
菜单栏与 iOS 桌面读的都是 `CFBundleDisplayName`，改它就够了。

iOS 的 `CFBundleName` 也保持 `night_sleep`：它是对内的短名（有 15 字节上限），
不显示给用户。

Android 平台目录不存在（`.metadata` 只有 ios / macos / web），`android:label` 无从可改，
记在 README「未实现」表里，随平台目录一起补。

## 二、数据模型：schema v3 → v4

新增一张**单行表** `ActiveSessions`。单行是刻意的：沿用 `AppSettings` 那条
`id = 'default'` 的既有约定，主键固定为 `'active'`，于是「同时存在两个会话」在结构上不可能发生，
不需要任何判重逻辑。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text，主键 | 恒为 `'active'` |
| `startAtUtc` | datetime | 点「开始睡眠」的真实时刻（UTC 瞬时值） |
| `timeZoneId` | text | 录入时区，与 `SleepRecords` 同口径 |
| `wakeMinutes` | int | 起床时间（距本地午夜分钟数） |
| `alarmEnabled` | bool | 闹钟开关 |
| `noiseId` | text，可空 | 选中的助眠音效 id（`null` = 没选） |
| `noiseVolume` | real | 音量，默认 `0.5` |
| `createdAt` | datetime | 写入时刻 |

`noiseId` 存 id 字符串而不是 `NoiseKind` 枚举：与 `SoundClips.kind`、`SleepStageSegments.stage`
的既有做法一致，读不到认识的 id 时按「没选」处理，不至于让一行坏数据把整个会话读不出来。

**`soundRecordingEnabled` 不进这张表。** 「鼾声/梦话记录」是一个**跨会话的偏好**，
它已经有家——`AppSettings.soundRecordingEnabled`。在这里再存一份会造出第二个真相来源，
两边一旦分叉（在会话页关掉、设置页却还写着开）就是这个项目明令禁止的那类 bug。
会话页那个开关**直接读写 `AppSettings`**，与设置页共用同一个字段。

`noiseVolume` 则相反，进这张表：现有的 `NoiseSheet` 把音量留在 widget 局部状态里，
没有任何持久化，所以这里不存在第二个来源，存下来反而让会话能记住昨晚调到多少。

### 第二处改动：`SleepRecords.quality` 改为可空

会话结束时会就地弹一次星级（见 §三），**跳过则质量留空**。于是 `quality` 必须能表示
「用户还没评过」——这正是 `SleepQuality` 目前缺的那一档（它只有 1–5，没有未评分）。

这不是可选的：填一个默认的「一般」等于替用户说了他没说过的话，而且会凭空带进
`estimateScore` 里 35 分权重中的 17.5 分。项目红线禁止这类伪造。

**好消息是「没有评分」这条路已经铺好了**：`SleepStatistics` 早已按 `e.score != null`
过滤并把空集的平均分记为 `null`，`SleepEntry.score` 也有完整的空值分支，
首页 hero 卡与记录卡的评分行都已经写成 `if (score != null)`。这次要做的只是让
`quality` 真的能为空，再把 `scoreSource` 的第一道判断改成「质量为空 → `none`」。

`estimateScore` 的公式**一个字节都不动**——未评分时它根本不会被调用，而不是被喂一个假值。

### 迁移：v3 → v4

`onUpgrade` 新增 `if (from < 4)`，做两件事：

1. `m.createTable(activeSessions)`。
2. `m.alterTable(TableMigration(sleepRecords))` —— **SQLite 不能原地改一列的可空性**，
   drift 的 `alterTable` 走的是「建新表 → 拷数据 → 删旧表 → 改名」。`quality` 在表定义里
   改为 `integer().nullable()`，既有行的值一个不动地拷过去，`NOT NULL` 约束随之放开。

第 2 步是本项目第一次重建一张**有子表引用它**的表（`sleepStageSegments` / `soundClips` /
`insights` 都指向 `sleepRecords`）。迁移期间 `PRAGMA foreign_keys` 是关着的
（`beforeOpen` 要等迁移跑完才打开），子表里存的 `record_id` 是文本值、重建前后不变，
所以改名之后引用仍然成立——但这正是 v3 那次踩过坑的同一类位置（**顺序与开关状态**），
必须有测试钉住：迁移后级联删除仍然生效、孤儿行为与 v3 一致。

没有数据回填。v3 库里的每一条既有记录质量都是非空的，升级后照旧。

**删除全部本地数据**时会话表一并清空——一个残留的会话会在下次启动时凭空长出一条记录。

## 三、会话生命周期

```
idle ──「开始睡眠」──▶ 写 session 行 ──▶ 推入 /sleep/session
                                            │
                    「收起」（离开页面，会话继续）◀────┤
                                            │
                        「结束睡眠」──────────┘
                              │
                    时长合法？ ──否──▶ 说明 + 「手动补录 / 丢弃这次会话」
                              │是
                    ┌─ 昨晚睡得怎么样？ ─┐   ← 就地评一次，可跳过
                    │  ★ ★ ★ ★ ★        │
                    │  [ 跳过 ] [ 保存 ] │
                    └──────────────────┘
                              │
                  一个事务：写 SleepRecord(source='session') + 删 session 行
                              │
                          取消通知 9003（尽力而为，在事务之后）
                              │
                    ✓ 已记录 7h48m ──▶ 切「回顾」Tab
```

**为什么评星要放在结束这一步**：刚醒那一刻是主观感受最清楚的时候，隔几小时再回来看，
「睡得怎么样」就只剩一个模糊印象了。跳过仍然允许——但跳过就是**留空**，不是填个中间值。

**取消通知排在事务之后**，因为取消通知是一次平台调用，进不了数据库事务。
顺序不能反过来：先取消通知再写库，一旦写库失败，用户就得到「闹钟没了、记录也没有」的最坏组合。
反过来的失败（记录写好了、通知没取消掉）只会多响一次——而 9003 是**一次性**通知，
响过就没了，代价可接受。

### 四条硬约定

1. **记录里的两个时刻都是真值**。`startAtUtc` 是点「开始睡眠」那一刻，`endAtUtc` 是点
   「结束睡眠」那一刻。没有「估计你几点睡的」，也没有任何反推。
2. **结束后那条记录 `stages` 传空 list，不是 `null`**。`null` 在仓库层的语义是「保持已有阶段
   不变」（规格 5.2），对一条全新的记录两者等价；显式传 `[]` 是为了让「会话不产生阶段」这件事
   在调用点就写明白，不至于日后被人照着 `null` 抄进一个编辑路径。
3. **时长守门**：结束时若时长不在 `(0, 24h]` 内，**不落库**。弹一个说明，给两个出口——
   「手动补录某一晚」与「丢弃这次会话」。会产生这种情况的只有两种操作：点了开始就立刻点结束，
   或者点了开始忘了结束、放了三天。两种都不该静默变成一条睡眠记录。
4. **质量可空，且默认就是空**。跳过评星 → `quality = null` → 那条记录**没有评分**
   （`scoreSource` 返回 `none`），首页卡与记录卡不显示分数，统计的平均分把它排除在外。
   绝不填一个「一般」来占位。用户在回顾页或编辑页评了分，分数才出现。

### 开始会话时的初值

点「开始睡眠」写入的那一行，各字段的来源必须是确定的：

| 字段 | 初值 | 理由 |
| --- | --- | --- |
| `startAtUtc` | `DateTime.now().toUtc()` | 用户按下的那一刻 |
| `timeZoneId` | 设备当前时区 | 与 `LogPage` 保存时的口径一致 |
| `wakeMinutes` | `AppSettings.wakeReminderMinutes`，为 `null` 时取 **07:00** = `420` | 用户多半已经在设置页设过起床提醒，复用它是自然的默认；没设过就给一个普通作息 |
| `alarmEnabled` | `false` | 见下 |
| `noiseId` | `null` | 不替用户选一个音 |
| `noiseVolume` | `0.5` | 与 `NoiseSheet` 的默认音量一致 |

**`alarmEnabled` 默认关**，不继承任何偏好。排通知需要通知权限，而权限只在用户真的去开
那个开关时申请（规格 §7：麦克风、通知只在使用相应功能时申请）。默认开着会让「开始睡眠」
这一步顺带弹一个权限请求，那是用户没要求的。

### 冷启动恢复

会话在数据库里，所以杀掉应用再打开，首页直接显示「正在睡眠」卡，会话页照常进得去。
不需要任何内存态兜底，也不需要 `main()` 里额外做一次恢复（与 `reconcileReminders` 不同：
那条是为了修「调度被系统清掉」，这里数据本来就在）。

### 醒来日归档

结束时的记录按**醒来所在的本地日期**归档（规格 5.2 的既有口径）。会话跨午夜是常态，
这条不需要为会话做什么特殊处理——`save()` 与 `SleepEntry` 已经按这个口径实现了。

## 四、会话页 `/sleep/session`

推入式全屏页，覆盖标签外壳（与设置子页同一个路由层级）。

### 收合态

```
┌──────────────────────────────┐
│ 23:14          夜深 · 睡眠中  │
│ 8月30日 星期六                │
│ 正在睡眠                      │
│                              │
│        ╭───────────╮         │
│       ╱  3h 42m     ╲        │   ← 日晷圆环
│       │   已入睡     │        │
│        ╲            ╱        │
│         ╰──────────╯         │
│                              │
│ 入睡 23:14 ───────── 闹钟 07:00│
│ ⏰ 起床闹钟已开 · 还有 3h 18m  │
│ ⓘ 由系统通知投递；休眠模式下   │
│   可能晚几分钟，强度不如系统闹钟│
│                              │
│ ┌──────────────────────────┐ │
│ │ ──                       │ │   ← 抽屉把手
│ │ ♪ 白噪音 · 音量 46%  调整 ›│ │   ← 整条可点
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

**圆环的语义：已睡时长 ÷ 计划时长。**

- 分子 = `now − startAtUtc`（真实流逝的时间）
- 分母 = `起床时刻 − startAtUtc`，其中起床时刻取**今天/明天里最近的那一个**
  （即 `nextOccurrence` 的口径：从会话开始时刻起，下一次落到 `wakeMinutes` 的墙上时刻）
- 画满即到点。超过起床时间后弧停在满圈不再增长，中心改显示「已超过起床时间 42m」，
  而不是让它溢出或回绕。

两个已知的、可接受的边界：

- **改起床时间会让弧长跳一下**。分母跟着变，这是对的——目标改了，进度本来就该重新算。
- **起床时间早于会话开始时刻**时（例如 23:14 开始、起床时间设成 23:00），
  最近的那次落在**明天** 23:00，于是计划时长接近 24 小时、弧几乎不动。
  这不是 bug，是「你设了一个已经过去的钟点」的正确后果；真到结束时那条 `(0, 24h]`
  的守门会拦住任何越界的结果。

**「定了几点起」在收合态就必须看得见**（`入睡 23:14 ─── 闹钟 07:00` 那一行）。
这条来自使用方的直接反馈：最早的版式把起床时间藏在抽屉里，等于睡前设完就再也看不到自己设了什么。

闹钟关掉时，胶囊换成「闹钟已关 · 自然醒后手动结束」。

### 抽屉（展开态）

**点摘要条打开**，不做纯上拉手势——躺着的时候拖拽不好使。展开后四组设定：

| 区块 | 内容 |
| --- | --- |
| 今晚的设定 | 起床闹钟 `07:00 ›` + 开关（一行）；鼾声/梦话记录 + 开关 |
| 白噪音 | 八宫格选择 + 音量条 |
| 说明 | 后台播放限制的如实标注 |

**起床时间与闹钟开关合成一行。** 这是使用方定的口径：起床时间就是闹钟时间，一个值；
开关只决定到点**响不响**。自然醒的人把开关关掉，醒来手动结束睡眠即可。
圆环的目标时刻两种情况都有值，因此圆环不需要「没有目标」的降级分支。

展开时圆环让位，但 `入睡 ─── 闹钟` 那一行**始终留着**。

### 收起

左上角一个「收起」按钮：`pop()` 回应用，**会话继续跑**。首页此时显示「正在睡眠 · 已睡 3h42m」
卡，点回来即可。结束会话只有「结束睡眠」一个入口，避免误触。

## 五、起床闹钟

### 为什么不能复用 `sync()`

现有的 `ReminderScheduler.schedule()` 写死了
`matchDateTimeComponents: DateTimeComponents.time`——那是**每天重复**。直接拿它排起床闹钟，
会得到一个每天到点都响、且永远取消不干净的闹钟。

同时 `sync()` 只取消 `9001` / `9002` 两个固定 id。这一点**必须保持**：否则每次启动的
全量重排会把会话闹钟一起抹掉。

### 接法

- 新增常量 `wakeAlarmId = 9003`。
- 新增方法 `scheduleOnce(ReminderRequest request, {required tz.TZDateTime when})`：
  与 `schedule()` 同样走 `zonedSchedule`，但**不传** `matchDateTimeComponents`。
- **`sync()` 不动 9003**，并在文档注释里写明原因。
- `reconcileReminders` 扩展为：除了既有的 `reminderPlanFrom(settings)`，再读一次活跃会话，
  按「有没有会话 + `alarmEnabled` + 权限」决定排还是取消 9003。

  这仍然是那条**同一个生命周期**原则：调度内容从数据库推导，不额外维护一份内存状态。
  启动路径与设置路径共用一份映射函数，两处各写一遍就会出现「开关开着却不响」。

- **排定时刻**：`nextOccurrence(request, now: tz.TZDateTime.now(tz.local))`。
  复用那个已有测试覆盖的纯函数，于是**夏令时口径免费拿到**——跨切换日时闹钟仍在同样的
  **墙上时刻**响，而不是「前一次的绝对时刻 + N 小时」。改起床时间时重新按 `now` 算一次，
  规则只有一条。
- 取消：会话结束时 `cancel(wakeAlarmId)`。

### 与日常「起床提醒」撞车怎么办

设置页那个「起床提醒」（id `9002`，每天重复）和今晚的起床闹钟是**两件不同的事**，
但它们可能被设成同一个时刻。两个都排上，用户会在同一分钟收到两条通知。

规则：**会话活跃期间，日常起床提醒 `9002` 让位。**

- 开始会话且闹钟开启时：`cancel(wakeId)`。就寝提醒 `9001` 不受影响——它说的是「该睡了」，
  与闹钟无关，会话期间照常有意义。
- 会话结束或被丢弃时：按 `reminderPlanFrom(settings)` 重新排回 `9002`。

这条也一并收进 `reconcileReminders`：启动时若发现会话活跃，就按「会话闹钟优先」重排。
于是这条规则和其余调度一样，只有一个推导来源，不需要任何额外标记位。

### 权限

与设置页完全同一条规则（规格偏差 #19）：用户打开闹钟开关时申请通知权限，
**被拒则不写入会话的 `alarmEnabled`、开关回弹**；权限已是 `denied` 时给「去系统设置」入口。

### 强度与诚实标注

| 平台 | 做法 | 为什么不是更强的做法 |
| --- | --- | --- |
| iOS / macOS | `interruptionLevel: timeSensitive`，可穿透专注模式 | `critical` 需要 Apple 单独批准一项 entitlement，本项目没有 |
| Android | `inexactAllowWhileIdle` | 精确闹钟要么多一个 `SCHEDULE_EXACT_ALARM` 授权流程，要么用需要上架审核的 `USE_EXACT_ALARM` |

界面上如实写着：**「由系统通知投递；休眠模式下可能晚几分钟，强度不如系统闹钟。」**
这句话是这次功能的一部分，不是免责套话——用户需要知道它和系统闹钟不是一回事。

**通知文案**：标题「该起床了」，正文「结束睡眠，记录一下昨晚睡得怎么样。」

## 六、回顾页（取代「记录」Tab）

`AppTab.log` 的 **`id` 保持 `'log'` 不变**，只把 `label` 从「记录」改为「回顾」。
id 是标签条取实心图标的键（`filledTabGlyph(tab.id, …)`），改它会让标签图标静默掉回描边态。
笔的图标继续用——「写感受」正好是它的意思。

### 页面结构

```
回顾
睡得怎么样？

┌─ 8月30日 星期六 · 昨夜 ────────┐
│ 23:14 → 07:02   7h48m          │
│ 来自：睡眠会话                  │
└───────────────────────────────┘

睡眠质量   ★ ★ ★ ★ ☆   不错
睡眠事件   [打鼾] [说梦话]
           [辗转] [噩梦]
备注       [________________]
[ 保存补充 ]

手动补录某一晚 ›
```

- 目标是**最近一条真实记录**（`source != 'demo'`）。最新一条是演示记录时向下找，
  全都不是真实记录时走空状态。
- 保存写回**同一条 `id`**，不新增副本，`createdAt` 不变，`stages` 传 `null`
  （这里正是 `null` 的正确用法：补充感受绝不能抹掉设备测到的阶段）。
- **未评分的记录，质量行没有任何星选中**（不是默认选中第四颗）。用户可以只勾事件、
  写备注就保存，质量继续留空。评了分才写回，那时评分才出现在首页与统计里。
- 复用 `LogPage` 的表单控件，但**页面本身是新的**：它有「正在补充哪一晚」的记录头，
  而 `LogPage` 没有。

**刻意不做「换一晚」选择器。** 回顾页固定针对最近一条真实记录——它的职责是「刚醒来那一屏」，
不是「所有晚上的编辑器」。要给更早的晚上补感受，走既有的路径：记录卡 → 睡眠详情 →
「编辑记录」。那条路径的表单**包含同样的字段**（质量星级、四类事件、备注），
所以没有能力缺口，只是入口不同。加一个选择器会让这个页面变成第二个「记录列表」，
和首页的「最近记录」、统计页的记录卡重复。

### 空状态与演示数据

- **没有任何真实记录**：空状态「还没有可回顾的记录」+ 「手动补录某一晚」按钮。
- **只有演示数据**：如实说明演示记录不可补充（沿用偏差 #11 的理由——改动演示行的时长会让
  阶段与窗口互相矛盾，且 `source` 一旦不是 `demo` 就再也匹配不上「清除演示数据」），
  同样给出手动补录入口。

### 手动补录入口

回顾页底部一个次要入口，推入 `/log/new`。这是原先「记录」Tab 保留下来的一条能力，
现在降级成二级页——**它没有消失**，只是不再占据一个标签位。

## 七、`LogPage` 的简化

`LogPage` 现在同时服务两个宿主：Tab 里的新建表单，与推入的编辑表单，靠 `_isEditing` 分叉。
回顾 Tab 取代它之后，**`LogPage` 永远是被推入的**，于是：

- 删掉 Tab 分支，`build` 恒返回 `Subpage(title: _isEditing ? '编辑记录' : '手动补录', …)`。
- 保存后统一 `pop()`；不再有「切回 `AppTab.home`」与「2 秒后重置 `_saved`」那段
  （推入页 pop 掉就没了，没有需要重置的下一次）。
- 新建分支的标题从「记录睡眠 / 今天睡得怎么样？」改为「手动补录 / 补上那一晚」。

**顺带修掉一处旧的默认值**：表单现在把 `_quality` 初始化为 `SleepQuality.good`，
于是「保存时没碰星级」= 记录成「良好」——用户从没说过这句话，界面上那四颗星是亮的，
所以看起来像个选择，其实是应用替他做的。质量改为可空后，**表单初始无选中**；
不选就不写质量，任何入口都一致（新建、编辑、会话结束的就地评星）。

这是一处可见的行为变化，记进偏差表（#26）。

这一处是这次改动的净收益：一个文件里少一条分叉，少一个跨页副作用。
**代价是 `test/pages_widget_test.dart` 里现有的表单保存用例需要跟着改**（它们目前假设
保存后切 Tab），实现时必须一并更新，不能只改实现。

## 八、首页改动

| 状态 | 显示 |
| --- | --- |
| 无活跃会话 | 主按钮「**开始睡眠**」，副标题「定好闹钟与白噪音，记录今晚」 |
| 有活跃会话 | 主按钮位置换成「**正在睡眠 · 已睡 3h42m**」卡，`onTap` 回到会话页 |
| 无任何记录 | 空状态的「记录第一晚」同样改为「开始睡眠」 |

首页不再有「记录昨夜睡眠」按钮——那条路径由回顾 Tab 承担。

## 九、界面上的诚实标注（汇总）

三处标注是功能的一部分，不是可选文案。任何一条被删掉，这个功能就开始撒谎。

| 位置 | 文案 |
| --- | --- |
| 会话页 · 鼾声/梦话开关下方 | 尚未接入录音，开关只保存偏好。 |
| 会话页 · 白噪音区 | 退到后台或锁屏后声音会停（后台播放未接入）。 |
| 会话页 · 闹钟开启后 | 由系统通知投递；休眠模式下可能晚几分钟，强度不如系统闹钟。 |

**会话页与它产生的记录都不出现任何睡眠阶段。** 首页 hero 卡那段「这一晚没有睡眠阶段数据。
手写记录只有起止时间和主观质量……」的现成文案会自动适用——会话记录确实没有测到阶段，
它与手动记录在这一点上没有区别。这条不需要新写文案，但**需要在测试里钉住**：
不能因为有会话就认为有了阶段。

## 十、与原型的有意偏差（新增条目）

接主规格第 8 章，编号续到 #23。

| # | 原型行为 | 本实现 | 理由 |
| --- | --- | --- | --- |
| 23 | 「记录」Tab 是一张手动录入表单（日期/入睡/起床滚轮 + 质量 + 事件 + 备注） | 「记录」Tab 改为「**回顾**」Tab：对最近一条**真实**记录补充主观感受；手动录入降级为二级页 `/log/new`，入口在回顾页底部 | 手动录入假设用户记得住昨晚的入睡时刻，而那正是睡前那一刻才有的信息。改由「开始睡眠」在睡前采集起点后，录入表单的职责就只剩下「补上忘记录的那一晚」，不该再占一个标签位。**手动补录这条能力没有消失**，只是换了入口层级 |
| 24 | 原型没有「开始睡眠」入口，也没有会话页 | 新增：首页主按钮「开始睡眠」→ 全屏会话页（日晷圆环 / 白噪音 / 起床闹钟 / 鼾声梦话开关），会话状态存 SQLite，跨重启存活 | 用户明确提出的新能力，原型无对应。**它不测量任何东西**：圆环画的是「已过时长 ÷ 计划时长」，两个数都来自用户自己按下的时刻与设定的闹钟，不是推断。鼾声/梦话开关只存偏好并如实标注 |
| 25 | 原型没有闹钟（提醒开关是纯装饰，见偏差 #19） | 起床闹钟接真实本地通知（新 id 9003，**一次性**排定，与日常重复提醒共用调度器但不同 API），iOS 用 `timeSensitive`、Android 用 `inexactAllowWhileIdle`，界面注明强度不如系统闹钟 | 与 #19 同一条理由：一个写着「开」却不会响的开关是规格书禁止的。不用 `critical` / 精确闹钟权限是**刻意的取舍**，且必须写在界面上，否则用户会以为它和系统闹钟一样强 |
| 26 | 原型的主观质量是 1–5 的必填档，无「未评分」态；记录表单默认选中「良好」 | `quality` 改为**可空**（schema v4 重建表放开 `NOT NULL`）。表单初始**无选中**；不选就不写质量，记录**没有评分**（`scoreSource` 为 `none`），统计的平均分把它排除。会话结束时就地评一次星，可跳过 | 「默认选中良好」是应用替用户说了一句他没说过的话，并且让 `estimateScore` 里 35 分权重的质量项凭空拿到 17.5 分。这条与偏差 #3「不显示读不到的余额」、#7「开关不得声称没有的能力」同源：**没有的东西就显示为没有**。代价是一次表重建，回归方法见 §11 的迁移行 |

## 十一、测试与验收

| 类型 | 重点场景 |
| --- | --- |
| 数据迁移 | v3 → v4：`ActiveSessions` 建表成功；`sleepRecords` 重建后 **`quality` 确实可空**（写入 `null` 成功）且**既有行的质量值一个不差**；**v3 的既有记录、阶段、片段、洞察、设置一行不动**；重建后子表外键仍然成立（插入阶段行后删记录，级联把它带走）；重复打开不重跑；全新库直接建到 v4 |
| 领域 | 未评分：`quality` 为 `null` 时 `scoreSource` 为 `none`、`score` 为 `null`、`estimatedSummary` 为 `null`（**不调用 `estimateScore`**，也不返回一个半权重的分数）；统计的平均分把未评分的记录排除在分母之外、全部未评分时平均分为 `null` |
| Widget | 评星就地弹窗：跳过 → 落库的记录质量为 `null` 且**没有评分**；评了 → 质量与评分都出现（变异验证：把跳过分支改成写入 `SleepQuality.fair`，断言必须变红） |
| 数据 | 会话开始/结束：写记录用了 `startAtUtc` 与结束时刻的真值、`source = 'session'`、按醒来日归档、结束时 session 行被删、级联与「删除全部本地数据」会清掉残留会话 |
| 数据 | 时长守门：0 时长与 > 24h **不落库**、不写记录、会话仍在（让用户选丢弃还是补录） |
| 数据 | 冷启动恢复：写入会话后重新打开数据库，会话仍在且字段原样 |
| 通知 | `scheduleOnce` **不传** `matchDateTimeComponents`（一次性，非每日重复）；`sync()` **不动** 9003（变异验证：让 `sync` 也取消 9003，启动重排抹掉闹钟的用例必须变红）；`reconcileReminders` 按「有无会话 + 开关 + 权限」排/取消 9003 |
| 通知 | 会话活跃且闹钟开启时日常起床提醒 `9002` 被取消、就寝提醒 `9001` 不受影响；会话结束后 `9002` 按偏好排回 |
| 数据 | 「鼾声/梦话记录」**只有一个真相来源**：在会话页改它，`AppSettings.soundRecordingEnabled` 跟着变，设置页读到的就是新值（反向护栏：会话表里不存在同名字段） |
| 通知 | 排定时刻复用 `nextOccurrence`：跨午夜（23:14 起 → 次日 07:00）与跨夏令时切换日仍落在同一墙上时刻 |
| Widget | 会话页：点摘要条展开抽屉；圆环进度随已过时长变化；超过起床时间后显示「已超过…」；三条诚实文案**确实在**（文案缺失必须变红） |
| Widget | 会话页：闹钟开关被拒时回弹且不写入会话 |
| Widget | 回顾页：无记录空状态；只有演示数据时不可补充并说明；写回同一 id；`createdAt` 不变；`stages` 传 `null` 时既有阶段不被清空 |
| Widget | 首页：有会话时显示「正在睡眠」卡且可回到会话页；无会话时主按钮是「开始睡眠」 |
| Widget | `LogPage` 恒以 `Subpage` 呈现（Tab 分支已删）；保存后 `pop()` 而非切 Tab |
| 资产/配置 | 显示名：iOS plist 的 `CFBundleDisplayName` 为 `夜深`；macOS plist 有该键；web 的 `title`、`apple-mobile-web-app-title`、manifest 的 `name` / `short_name` 均为 `夜深`；且 `PRODUCT_NAME` / `CFBundleName` **仍为 `night_sleep`**（反向护栏，防误伤构建路径） |

以上每条断言都要做**变异验证**：把实现拆掉、断言必须真的变红。不做变异验证的断言视为没有。

## 十二、未验证与已知限制

- **通知是否真的到点投递**：本机没有真机验证过（这是项目既有的未验证项，本次不改变）。
  Dart 侧的调度契约由测试钉住，但「到点真的响了」仍需人工确认。
- **`timeSensitive` 是否真的穿透了专注模式**：需要在真机上开一个专注模式实测。
- **后台/锁屏音频**：本次不实现，界面已如实标注。
- **Dock / 桌面显示名的实际观感**：plist 改了不等于系统重新读了缓存，需要在人工确认后
  才把这条划掉（与偏差 #16 的 Dock 图标是同一类问题）。
- **宽屏（macOS / 侧边栏）下的会话页与回顾页**：需要核对，不能默认窄屏版式直接拉伸。
