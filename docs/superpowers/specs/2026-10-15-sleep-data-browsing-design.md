## 问题

使用方 2026-10-15 提了两条：

1. **导出页只能看到条数，看不到内容**——「睡眠数据导出页面 支持表格预览查看数据展示」。
   当前导出页只有四个数字（记录 / 阶段段 / 声音片段 / 洞察），按下导出之前没有任何办法
   确认文件里到底写了什么。对本应用最较真的那条红线（不把没发生的事写进用户的数据）来说，
   一个可以打开看一眼的预览正好是它的界面凭据。
2. **统计页只看得到最近 7/14/30 条，没有地方翻全部记录**——「统计页面右上角新增一个
   查看所有睡眠数据的入口，然后在二级页面支持查看所有数据，支持按月、按周、按年查询」。

原型都没有这两个页面（原型是纯前端演示，数据不落地），所以两者都按偏差 #18 那一类处理：
**本实现新增，交付形态自定**，并记入总规格 §8 偏差表（#66 / #67）。

## 不做什么

- **不做 JSON 预览。** 预览的对象是 CSV 的两张表（记录 / 阶段）——它们是「表格」，
  有列、有行、能一格一格核对。JSON 是嵌套存档，把它铺成表格是在编造一种它并不具有的形状。
- **不做导出范围的时间筛选。** 导出始终是**全部真实记录**（上游规格定死），预览跟着它，
  不为预览单独造一套筛选——那会立刻产生「预览的筛选和文件的范围不是一个东西」的风险。
- **不在预览页里编辑数据。** 预览是只读的：它要回答的是「文件里有什么」，能改的话
  它就不再是文件的样子了。要改记录走详情页 / 回顾页。
- ~~**不给「全部睡眠数据」页加统计图表。**~~ ~~统计页已经承担了趋势、评分与汇总；这一页的职责是
  **翻阅**。重复一套图表只会让两处数字将来各自漂移。~~
  **2026-10-16 推翻，见下方 §二 的订正。** 那条顾虑本身没错，但原型更新后这一页确实带了
  平均时长柱状图与三个聚合数字，使用方裁定照原型做。**挡漂移的办法从「只留一套图表」
  换成「聚合成领域纯函数、两页共用同一份分母口径」**——分母规则仍锁在总规格 §5.2 一处。

## 一、导出表格预览（`/settings/export/preview`）

### 单元格与文件同源（这条是整个设计的支点）

预览里显示的每一格，必须是 CSV 文件里的那一格。实现上**不是**「照着 CSV 的规则再渲染一遍」
——那等于把格式知识抄成两份，早晚会分叉。改为在 `sleep_export.dart` 里把「表」抽成第一类
对象：

```dart
enum ExportTableKind { records('记录'), stages('阶段') }

/// 一张导出表：表头 + 已按 CSV 规则渲染成字符串的行。
class ExportTable {
  final ExportTableKind kind;
  final String fileName;
  final List<String> header;
  final List<List<String>> rows;
}

static List<ExportTable> tables(List<SleepEntry> entries, {required DateTime now});
static List<ExportFile> csv(...);   // = tables() 逐表拼成 CSV 文本
```

- 文件名、表头、行、单元格编号（`_recordRow` / `_stageRow`）都只在这一处产生；
- `csv()` 变成 `tables()` 的**序列化**，界面读的是同一个 `tables()`；
- 回归方法是一条**往返断言**：把 `csv()` 的产物按 RFC 4180 解析回来（去 BOM、认引号），
  必须与 `tables()` 的 `header` / `rows` 逐格相等（`test/sleep_export_test.dart`）。
  以后谁改坏了引号或列序，这条会红。

### 版面

路由 `/settings/export/preview`，`Subpage(backLabel: '导出', title: '表格预览')`。

1. `SegmentedControl<ExportTableKind>`：**记录 / 阶段**，与两张 CSV 一一对应；
2. 一行灰字写**真实文件名**（`夜深-睡眠记录-20261015.csv`）与**总行数**——文件名里的日期戳
   正是按下导出时会拿到的那个，用户对着它就知道自己看的是哪份文件；
3. 表格本体：表头一行 + 数据行，横向滚动（16 列放不进 390px），列宽固定、单元格内换行；
4. 说明：预览与文件逐格相同、文件走系统分享面板、演示记录既不进文件也不进预览。

**「事实」块（文件名、总行数、截断说明、排除条数）排在表格之前。** 这张表可以长到几千
像素，说明写在它后面等于要用户先滚过 50 行才知道自己看的是节选——先说清楚，再给数据。

**行数上限 50 行，并在页面上如实说明**（「预览只显示前 50 行，文件包含全部 N 行」）。
理由是这一页的意义是**抽查**而不是通读：整张表一口气建成几千个 `Text` 是拿启动时间来换
一个没人会读的完整性；而**少显示的部分必须说出来**——这与「没有的东西就显示为没有」是
同一条规矩的两面。

**空状态**：可导出记录为 0 时显示「暂无可预览的记录」，并照旧报出被排除的演示记录条数
（演示数据是唯一会被排除的来源）。

**导出页本身也要分三态**：读不到记录时不许说「暂无可导出的记录」。这一页此前把
`AsyncError` 与加载中都退化成空列表，于是「读不到」被说成了「没有」，三个动作一起置灰；
现在加载转圈、出错写「无法读取记录 + 原因」、有数据才进内容分支——与它推入的这一页同一口径。

**入口**：导出页 `IosListGroup` 的**第一行**——「预览表格」/ 副标题「先看看将写进文件的两张表」，
排在两个导出动作之前。没有可导出记录时与两个导出动作一样**禁用**（该页既有的口径：
没有的东西就不给一个点了没反应的入口）。

## 二、全部睡眠数据（`/stats/all`）

> ### ⚠️ 订正（2026-10-16）：下面这半节描述的是 v3.31 的形态，**已被取代**
>
> 原型更新后（Figma Make `hKbqp1qjtcNQmmiDtVvXpk` 末层）这一页整体换了形态：
> 从「分段控件 + 一次列出全部组」变成「**周 / 月 / 年 + 周期翻页 + 一张按周期的汇总卡
> （平均时长、柱状图、平均评分 / 达标率 / 记录夜数）+ 一个扁平记录列表**」。
> 使用方 2026-10-16 原话：「统计页面的查看所有数据的页面整体展示都变了，请重新实现一下」。
>
> **当前形态以[静谧夜色 + 柔和晨光 §4.5](2026-10-16-quiet-night-visual-language.md) 为准。**
>
> 从下面四小节**保留下来**的：分组用醒来本地日、一周从周一起算、
> 用 `DateTime(y, m, d - n)` 构造而不是 `subtract(Duration)`、周标签带年份、
> 平均时长分母是记录条数、平均评分只计已评分、`估算` / `评分` 的措辞区分、演示记录照列并报数。
> **被取代的**：组的罗列形态（改为按周期翻页）、组抬头（改为周期标签 + `N 条睡眠记录`）、
> 全库汇总卡与覆盖范围行（改为按周期的汇总卡）、「条目只列不画图」。
>
> **`HistoryGrouping` 的三个标签同时从 `按周 / 按月 / 按年` 缩成 `周 / 月 / 年`**（照原型的
> 分段控件），因此 §五 测试矩阵里点名 `按周` / `按月` 的那几条断言要跟着重钉。
> 下面各小节原样保留，作为 v3.31 的当时记录，不要照它实现。

### 入口

统计页标题行右上角，一行「全部数据 ›」（`Pressable`，`semanticLabel: '查看所有睡眠数据'`）。
**只在库里有记录时出现**：一条记录都没有时它通向一个只能显示空状态的地方，那是个死胡同，
而统计页那一刻已经在说「暂无统计数据」了。

### 分组口径

`HistoryGrouping { week('按周'), month('按月'), year('按年') }`，默认**按月**。

- 归组用的是**醒来所在的本地日历日**（`SleepEntry.archiveDay`）——与总规格 §5.2
  「统计以本地日历天分组，跨午夜记录按醒来日期计入一天」同一条口径；
- 一周从**周一**起算（中文语境的「本周」）；起算日由 `DateTime(y, m, d - (weekday - 1))`
  构造，**不是** `subtract(Duration)`——后者在有夏令时的时区会把本地午夜推成前一天 23:00；
- 组标签：月 `2026年10月`、年 `2026年`、周 `2026年10月12日 – 10月18日`（跨年时两端各带年份）。
  周这一档的年份**不能省**：行里只有「10月14日 周三」，年份全靠抬头给，而相隔若干年的
  同一个日历区间可以逐字相同（1 月 5 日都是周一的那两个年份）；
- 组间**最新在前**，组内也是最新在前（`SleepHistory.from` 自己排序，不沿用调用方给的顺序——
  与 `SleepExporter.exportableOf` 同一个理由：别让界面顺序悄悄决定数据顺序）。

### 每组的抬头与聚合

抬头左侧是组标签，右侧一行 `N 晚 · 平均 X.Xh`；**组内有已评分的记录时**再追加 `· 评分 Y`。

- 平均时长的分母是组内**记录条数**（漏记的日子不稀释平均），沿统计页既有的分母规则；
- 平均评分**只计有评分的记录**（分子分母都排除未评分的），一组里一条都没评分时
  **不显示这一项**——不显示一个并不存在的平均分。

页面顶部另有一张汇总卡：记录数 / 平均时长 / 平均评分（全库无评分时这一格写「未评分」），
以及一行覆盖范围 `覆盖 M月d日 – M月d日`（跨年时带年份）。

### 记录行

日期 + 周几（`10月14日 周三`）、`23:10 → 07:05`，右侧时长（`8h 5m`）与分数
（**未评分就不写这一行**，不写占位符）。

**分数要写清是哪一种**：`SleepEntry.score` 可能是模型给的，也可能是本地规则按质量与时长
估出来的（`isEstimated`）。后者写「估算 NN」、前者写「评分 NN」——与首页同一条口径
（`home_page.dart` 的 `isEstimated ? '估算' : '评分'`），详情弹层里也是分开标的。
**估算顶着「评分」两个字出场就是把本地规则说成了模型结论。** 汇总卡与组抬头里的平均分
是两者混在一起的，所以页面脚注里写明「评分可能来自模型，也可能是本地规则估算」，
并指出点开某一晚能看到这一晚是哪一种。点一行打开既有的睡眠详情弹层（`showSleepDetailSheet`）——编辑与删除照旧走详情页
既有的两条路径，这一页**不新增**任何写路径。

### 演示记录

与统计页**同口径**：统计页的 `SleepStatistics.from` 并没有过滤演示记录，这一页也不过滤。
演示数据在调试构建里本来就出现在首页与统计里，没有理由在这一页突然消失；而「全部数据」
若悄悄少掉几条，那才是这一页最不该犯的错。

但**照列不等于不作声**：汇总卡里那三个数字把合成的与真实的混在一起，所以库里含演示记录时
在卡片末尾补一句「其中 N 条是演示数据，不是你的记录」（首页对同一个库也挂着横幅，
点进详情弹层才看得到「这是演示数据」）。只有调试构建里会有这句。

### 空状态

`EmptyState`：标题「还没有睡眠记录」，正文说明记录第一晚之后这里会按周 / 按月 / 按年列出全部记录。
它是**可达的**：从这一页打开某晚详情、在详情里删掉最后一条记录，页面会当场变成空状态。

## 四、取舍

- **50 行的上限**是刻意的：拿「通读整表」换「打开够快」，并把少显示的那部分写出来。
- **预览只覆盖 CSV**：JSON 不做预览（见「不做什么」）。
- **「全部数据」不做时间筛选控件**：按周 / 按月 / 按年已经是查询口径，再叠一个「跳到某月」
  的日期选择器，是让同一件事有两个入口。
- **演示记录照列**（与统计页一致），**导出预览里则不出现**（与导出文件一致）。两处口径不同
  不是矛盾：导出的语义是「我的数据备份出去」，统计与翻阅的语义是「应用里现在有什么」。

## 六、未验证

- **界面目视核对没做**：两页在浅色 / 深色、手机 / 宽屏下的实际观感（表格列宽是否够读、
  横向滚动的手感、组抬头的疏密）只有几何与结构断言，没截图核对。宽屏下表格是否该多留白
  也没有结论。
- **真机手感未验证**：横向滚动与外层纵向滚动手势的冲突在真机上是否顺手，只在 widget 测试
  里点过。
- 记录条数很大的库（数千条）上「全部数据」页的滚动性能没有量过；50 行上限的取值因此是
  拍的，不是测出来的。
